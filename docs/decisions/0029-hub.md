# 0029 · A hub holds many workspaces, added from the app

A host is still one workspace (`kuraa-host --dir`). A **hub** is one server, one address and one
token, for many: started with `kuraa-host --workspaces <folder>`, and embedded by the desktop
app. People add workspaces from the app, as a new folder or by joining one from an invitation or
subscription link (0028), and switch between them.

**How it is built** (`packages/host/src/hub.ts`). The hub runs a host for each workspace, in its
own process, each on a loopback port of its own with the hub's token, and passes `/w/<id>/…` to
it: HTTP as it comes, and WebSockets (rooms) as a tunnel after rewriting the upgrade request. A
workspace's client therefore talks to `<hub>/w/<id>` exactly as to a host of its own, and the
host is unchanged; git works there too (`<hub>/w/<id>/git`). The hub's own API is under
`/hub/api`: list the workspaces, add one (`kind: new` with a name, or `kind: join` with an
invitation or link and a name), and take one off the list (its folder stays). The list is kept in
`<folder>/.kuraa-workspaces.json` (the desktop app keeps it with its own data). A workspace whose
folder is gone stays on the list, with why it cannot open. Requests for `/api/…` at the hub's root
answer 404, which is how a client tells a hub from a host.

**What may be added is the operator's to decide** (0018). New workspaces go only in the hub's
folder, named from the workspace's name (`Field notes` → `field-notes`, `-2` if taken), made git
repositories on git's configured default branch, else `main`. Joined workspaces go there too,
and sync with other devices; others sync only with `--peer`. Adding a folder from anywhere else on
the computer is for the desktop app alone, which is its own operator: **Open a folder…** adds the
folder the person picked (made a repository first if they agree).

**In the client.** On a hub, the workspace's name at the top of the sidebar opens a menu of the
hub's workspaces, **Add a workspace…**, **Open a folder…** (desktop), and **Remove from this
list…**. With none, the page offers to add one. The open workspace is remembered for the hub (and
`?w=<id>` opens one), and the open file for each workspace. Against a host, nothing changes.

**The desktop app** starts with your workspaces (new ones in `Documents/kuraa`; `--workspaces`
names another folder), not the launcher. `--open <folder>` adds and opens a folder; `--join` joins
someone else's host or hub as before, and **Join a shared host…** leaves for the launcher, which
also leads back to your workspaces.

**Inviting people** to a hub's workspaces from the app is allowed: **Invite people…** makes a
subscription link or an invitation (0028), turning syncing on for that workspace for good.

**Not yet:** `pnpm dev` runs a host of one workspace.
