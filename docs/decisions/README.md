# Decisions

One short note per deviation from, or interpretation of, the prototype build spec.

| # | Decision |
|---|----------|
| [0001](0001-node-only-typecheck.md) | One root TypeScript config; packages export their TypeScript source |
| [0002](0002-declarative-node-views.md) | Format packages describe node views as data; the client implements them |
| [0003](0003-pandoc-extension-point.md) | `createPandocType` is the extension point R Markdown builds on |
| [0004](0004-oracle-known-differences.md) | Pandoc constructs the parser does not yet match, and the oracle allow-list |
| [0005](0005-fuzz-normalisation.md) | What the fuzz test treats as equal |
| [0006](0006-client-shells.md) | The shell supplies document types; one client build loads from a host, Vite or `file://` |
| [0007](0007-history-paths.md) | History entries carry the file's path at each commit, so versions from before a rename open |
| [0008](0008-markdown-cues.md) | No toolbar or top bar; formatting comes from typing markdown; history starts closed |
| [0009](0009-shell-boundary.md) | The host does all file and git work; the client sees its shell through one interface; `pnpm dev` |
| [0010](0010-text-format.md) | One Text file type for source and data files: a ProseMirror node per line, highlighted by file name |
| [0011](0011-running-chunks.md) | Running R chunks: one R session per document on the host, shared outputs, never in the file |
| [0012](0012-format-editor-modules.md) | Each format brings its editor behaviour in an editor module; the client keeps only what is generic |
| [0013](0013-run-plugins-and-sandboxing.md) | Running code through engine and environment plugins (see 0018, 0019) |
| [0014](0014-packages.md) | Packages: declared per workspace in a committed manifest, stored once per host, installed apart from the data |
| [0015](0015-editable-source.md) | The Source view is editable, with character-level merging against the rich view |
| [0016](0016-vue-client.md) | The client's components are Vue; editor objects are never made reactive; plugins stay framework-free |
| [0017](0017-components-panel.md) | Components… shows the host's engines, environments and formats, and turns your own editing behaviour on and off |
| [0018](0018-untrusted-users.md) | (Superseded in part by 0047) People using the app are not trusted: code runs only in Podman, nothing in a document runs in the app, configuration is flags |
| [0019](0019-engine-and-environment-components.md) | Engines and environments are separate components meeting through run-kit; the host imports none; unsandboxed needs a flag |
| [0020](0020-components.md) | What extends the app (formats, engines, environments) is called a component, in the interface and the code |
| [0021](0021-document-header.md) | A document's YAML header is edited in a Header dialog (right-click the file), not in the page |
| [0022](0022-titles-and-filenames.md) | Documents are known by their title; filenames are made from it, safe for every file system and git |
| [0023](0023-file-icons.md) | Each document type defines its files' small icon; the client draws them all alike |
| [0024](0024-out-of-date-outputs.md) | Every run records what its session had run before it, so outputs computed from code that has since changed are flagged, and Rebuild above runs only what is behind |
| [0025](0025-merging.md) | Merges read documents (blocks, then words), never stop, and keep a conflict in the document as a block with both versions; the same merge commit on every device |
| [0026](0026-commit-messages-and-history.md) | Automatic commits name the document, the headings that changed and who edited, with an autosave trailer; history folds them into editing sessions |
| [0027](0027-room-seeds.md) | A room starts from the git blob of its file, seeded by a fixed client id, so rooms on different devices combine without duplicate text |
| [0028](0028-peers.md) | Devices of one workspace sync directly (Hyperswarm): pairing by invitation or subscription link, git between them, pull only, with the same merges everywhere; rooms join across devices; an upstream by convention, with gated branches and proposals (the upstream replaced by 0032) |
| [0029](0029-hub.md) | A hub serves many workspaces at one address (each a host, at /w/<id>); the app adds them as new folders or from invitations and links, inside the folder the operator named |
| [0030](0030-one-kind-of-server.md) | Every server is a hub: --dir serves one folder that nothing is added to, --workspaces a folder of them; the app always shows the workspace menu, offering to add only where the server allows |
| [0031](0031-signed-membership.md) | Membership changes are signed records passed on by any device; devices sign the commits they make (not merges) with git's SSH signatures |
| [0032](0032-accepting-work.md) | (Superseded by 0038) Each device decides whose work comes in on its own, by branch (others' waits as a proposal), and whose membership changes it takes; shared rooms are committed by a device all the others accept; no upstream: a sync remote is only an ordinary git remote |
| [0033](0033-document-rules-and-people.md) | (Superseded by 0038) Rules name folders and files (others' changes there are kept out, their history taken; their version can be taken later), are published as signed records, and may name people; live edits follow them; the editor opens documents others would not take your edits to read-only |
| [0034](0034-signatures-are-people.md) | A person's key signs every commit made on a computer that keeps one (else the device's key does); every host is one person; work is judged by who signed it as well as by the device it came through |
| [0035](0035-identities-and-signing-keys.md) | (Rules part superseded by 0038) A signing key per person per computer signs commits; a person's identity vouches for their keys (and revokes a lost computer's); connection keys only connect; rules name identities, keys or devices |
| [0036](0036-backups.md) | (Superseded by 0039) Backups: plain git servers (GitHub, GitLab…) pushed to after each save, never fetched from or force-pushed, with the person's own credentials; set up from the app where the host allows it |
| [0037](0037-host-safety.md) | The host never follows links, reads a file before writing it, pauses during git operations run outside the app and follows branch switches (committing the old branch's edits by its ref), does not open files that are not UTF-8, and retries failed saves |
| [0038](0038-equal-peers.md) | Every member of a workspace has the same say: no rules, every member's work comes in, one kind of invite link, identity made automatically; known weaknesses left to the coming redesign |
| [0039](0039-online-copy.md) | One online copy (GitHub, GitLab, any git server): each save pushed, fetched and merged on Sync and every few minutes, a refused push followed by fetch, merge, push; never forced |
| [0040](0040-writing-in-the-editor.md) | Writing in the editor: citations typed or picked from the bibliography (chips, unknown keys marked), images pasted into images/ beside the document, display math, pipe tables, find and replace, the outline, and conflicts visited in turn |
| [0041](0041-rendering.md) | Documents render to HTML, Word and PDF (Typst, or LaTeX where asked and present) through the run contract, where code runs, read-only and offline; outputs in .git/kuraa/renders, previewed in a frame that runs nothing |
| [0042](0042-search.md) | Search every text file with git grep (untracked too, ignored and binary and large files and links left out), open documents from their live rooms; a result opens at the match |
| [0043](0043-past-versions.md) | Past versions are labelled by date and people, compared with now by blocks then words, and restored as an edit in the live document; the desktop app's right-click menu |
| [0044](0044-polish.md) | The app teaches itself (a placeholder, Markdown and shortcuts from the editor modules' own key tables, a welcome), says what is happening in plain words with Details for experts, keeps focus in dialogs and works the file tree from the keyboard; one string catalogue; ⌘, is the page's menu, Preferences ⌥⌘, |
| [0045](0045-tools.md) | Tools (TinyTeX first) are a fourth kind of run component: downloaded on request where installs are allowed, stored once per computer, mounted read-only only into the processes that use them; LaTeX packages added in two steps, recorded per workspace |
| [0046](0046-desktop-preferences.md) | (Superseded in part by 0047 and 0048) The desktop app's Preferences set what a host's flags set (common ones in view, the rest under Advanced, validated, flags still winning); serving others, loading components and turning off the sandbox stay on the command line |
| [0047](0047-browser-equals-desktop.md) | The browser is the desktop app's equal: on a host listening only on this computer, whoever has the access code is its owner (Preferences, Open a folder…, identity, online copy); one settings model in the hub, applied in place; `--manage-person`, `--manage-online`, `--allow-invites` gone; code-running choices (`--component`, `--allow-unsandboxed`, `--podman`) stay flags |
| [0048](0048-shared-workspaces-always-sync.md) | A shared workspace (invited from, joined, forked) always syncs, and one on this computer alone has nothing to sync with: `--peer` and the **Sync every workspace** preference are gone; joining uses the servers set in Preferences |
| [0049](0049-joining-on-slow-networks.md) | A join in the app hands its still-connected node to the workspace's host instead of connecting anew; devices say whom they are connected to (a device reached through another is online through it; the lower key of two dials), and one lookup of the workspace, backing off, runs while one is missing, instead of dialling each missing device; joining reports its steps (`GET /hub/api/joins/<id>`) and the dialog says them, and when the network is slow |
| [0050](0050-networking-review.md) | Members offer each other blind relays (and `kuraa-host relay` runs one to name), devices find each other on the local network too, and every workspace shares one DHT node per computer, whose known nodes are kept; invite links carry a topic, not the secret, which is made anew when a device is removed, and topics change weekly; membership is what the records say (reconciled), hellos carry a hash of the records and the branch tips, so devices fetch and send only what is missing; git streams wait for their reader |
| [0051](0051-the-app-updates-itself.md) | The desktop app updates itself with `electron-updater` from signed releases (GitHub Releases or any https folder, set at build time by `KURAA_UPDATES`), downloading only what changed, put in place on quitting or with **Restart now**; Windows ships an installer; devices say which protocol they speak, do not sync across protocols, and show "newer kuraa" or "older kuraa", the older looking for an update at once |
| [0052](0052-the-server-updates-itself.md) | Each release carries the server on its own (one folder, needing only Node and git, signed with an Ed25519 release key built into every server); `kuraa-host install [--service]` puts it in a versioned folder of its own with a systemd or launchd service, and `--auto-update` takes a newer signed release every six hours and restarts at night, or at once when a device runs a newer kuraa |
| [0053](0053-reaching-each-other.md) | Devices reach each other through a device both reach (end-to-end tunnels on its links), over TCP to a server's address (`--peer-port`, `--public-address`, for networks that block UDP), and over one link per pair of computers for every workspace they share; invite links name relays and servers; named relays are shared; a server can be the DHT starting point (`--dht-port`); quiet local connections close; multicast on every network; **Devices** says how each is connected and when it was last seen, and what this computer's network allows; the desktop app keeps a log file |
| [0054](0054-document-settings.md) | The open document's own things (views, versions, saving, writing, its code session and its header) are in **Document settings**, a panel of the menu, opened from the menu or by right-clicking a file; the menu is for the workspace and you; a file's right-click menu has Document settings…, Rename… and Delete… (no Open, New file or folder here, or Move to…) |
| [0055](0055-title-in-the-page.md) | A Pandoc document's title is its page's top heading, typed there and written to the header's `title` field alone (only the characters that changed); a document without a header shows an empty title, and typing one makes the header |
| [0056](0056-new-files-at-once.md) | New file makes an untitled Markdown document at once (no dialog), opened with the cursor in its title; when it is left, its filename is made from the title typed; Rename… chooses any file's kind (its extension), and a text file renamed to a document gets its first title |
| [0057](0057-opening-files-quickly.md) | Opening a file does not wait behind the host's other work: saving with nothing changed runs no git; the file shows from disk at once while its room connects; rooms are kept warm (15 minutes, at most 24) and asked for when the pointer rests on a file; rooms open apart from the queue unless an outside change must be merged; a new room is parsed once |
| [0058](0058-shared-outputs.md) | Run outputs reach the workspace's other devices: each publishes its cache as a signed, parentless commit on `refs/kuraa/outputs/<device key>` (not a branch: never merged, checked out, backed up or pushed online), fetched with the branches and passed on, the newest of each device's kept; an output from another device says where it ran; clearing one clears it everywhere |
| [0059](0059-online-copy-is-a-component.md) | The online copy is a component (`@kuraa/sync-git`, in `@kuraa/run-components`): syncs are a fifth kind of run component (`RunComponent.syncs`, the `Sync` contract in run-kit), opened by the host for each workspace; `/api/syncs` replaces `/api/online`; set up in **Components…**, not the menu |
| [0060](0060-one-settings-window.md) | One Settings window: **You** (name, email and colour saved as each is changed, with no button; your key; the server and access code, with their own button) and, for its owner, **This computer's server** (what Preferences held, with its own button); opened from the menu's **Settings…**, ⌥⌘, and the desktop app's menu |
| [0061](0061-one-name-for-a-workspace.md) | One name for a workspace, the same for everyone: kept in it (`.kuraa/workspace.json`), given by whoever makes it (or, for one made before, by whoever first invites to it); joining asks for none; **Rename workspace…** renames it for everyone, as a commit that syncs; each device's list follows; two renames at once keep the first |
| [0062](0062-outputs-as-they-happen.md) | Run outputs reach connected devices with the document open as they happen (about 50 ms, not 1.5 s): each run's changes, its plots as bytes, on the link's own `kuraa/outputs/1` channel, believed only from the device that ran it, kept until a git commit of its holds them; another device's run under way shows where it runs, without Stop; git stays what everyone ends up with, and is quicker (publish soon, outputs fetched in a queue of their own, nothing serialised or read twice); `KURAA_TIMINGS=1` logs each step |
| [0063](0063-settings-keep-what-you-change.md) | Closing a settings window never loses what was changed: Settings applies server changes on closing (**Done**, Escape, a click outside), saying so, with **Discard changes** if a value is refused; Document settings writes the header as it closes; the workspace menu holds the workspaces, then **Add a workspace…** (which now also opens an existing folder), with invite and remove in the menu; where code cannot run, Run's tooltip says why; joining a shared server is gone from the interface (`--join` stays) |
| [0064](0064-four-kinds-of-settings.md) | Settings is one window of four sections, by who each applies to and where it is kept: **You** (this browser), **Document** (its file: the header), **Workspace** (its name, packages, devices, online copy, removing it) and **Server** (its settings for its owner; what it runs and its tools for all), each saying so first and opened at from wherever Settings is opened; the Components dialog is gone; the menu holds commands, not settings |
| [0065](0065-no-menu.md) | No menu: ⚙ at the bottom of the sidebar (and ⌘,) opens Settings at the open document, else the workspace; the open document's ⋯ (top-right) holds what to do with it (views, versions, writing, code session, Document settings…, Markdown and shortcuts); Search and Sync are beside + in the sidebar |
| [0066](0066-permissions-without-a-centre.md) | *Built (but server-held identities, passkeys and a sequencer, which wait on a design for shared servers): identities; the policy, with admins and members; who may change what (suggestions since removed: 0072); changes at the same time, cutoffs, merges checked; who reads what, with spaces; attestations, trustees, escrow (removed since 0078).* Who may read and change what, without a centre: identities are stable IDs whose keys change (a recovery key named in advance, trustees, optional escrow) and carry attestations (email, ORCID, GitHub, a domain) from verifiers each workspace names; a workspace has a genesis and a signed policy (`refs/kuraa/access`) of groups with admins and members and write rules by path, applied in every device's merge alike (refused changes kept out; rooms follow; documents open read-only); concurrent changes resolved alike (by rank since 0072, by what gives less since 0078; cutoffs); read boundaries per file by spaces, one git repository per audience, laid over one another into one folder |

| [0068](0068-people-and-their-computers.md) | Workspace settings' **People and computers**: each person with their computers (others apart); **Lost or no longer used…** on a computer, for its own person (admin or not: its key revoked too, where the identity is here) or an admin; devices take a removal from an admin's device or the same person's; a new secret is any member's; email checks shown only once a verifier is named |
| [0069](0069-permissions-on-files-and-folders.md) | One kind of permission, on a file or folder: who may change it, and (a folder's) who reads what is in it, the nearest up the tree counting; a private path named by its hash; permissions (and files of spaces) go with renames and moves, which only an admin may make of what has its own; new files in a folder fewer read go straight into its space; **Permissions…** on folders too; the file list marks who reads and who changes; Workspace settings' **Permissions** is an overview |
| [0070](0070-an-owner.md) | An owner above the admins: whoever made the workspace (one from before: whoever sealed it); only the owner makes, unmakes or takes out admins (and invites as admins, and removes an admin's computers); the owner stays, giving the role to someone else with **Make owner…** and staying an admin |
| [0071](0071-network-review.md) | What a review of the network found, and the fixes (`PROTOCOL` 4): git served as protocol v0 so hidden spaces cannot be fetched by id; branches and links only to paired devices; pairing by a member counts once the person came in by an admin's grant; grants sign their link's expiry and maker; records dated far ahead wait; revocations' cutoffs from the person's own devices, all kept; records compared by what they say and a want answered once; Hyperswarm's bans lifted when a link closes; lookups go on while anyone is missing; one relay per process; retries per device with backoff; spaces forward-only and checked against the policy |
| [0072](0072-ranks-devices-and-changes-not-kept.md) | How the policy is worked out, written down ([docs/policy.md](../policy.md)) and checked over histories made at random; changes at the same time settled by rank (owner, then admins and members by how long they have been); no suggestions (what one may not change opens read only); changes kept out listed in the file's history, *not kept*, and their maker told once; devices in as their people are (no pairing: a computer removed by dropping its key, `drop`; hellos carry the records that show a device is in); a revoked key's past word stands; folders hold a space of their own whose readers change in place; removals confirmed by acknowledgements, and witnesses; `PROTOCOL` 5 |
| [0073](0073-encrypted-spaces.md) | *Proposed.* Spaces a device can hold without reading them: an epoch key per space sealed for each reader's computers (from their signing keys), a new epoch when someone stops reading; holders keep sealed packs, and the online copy keeps them as blobs |
| [0074](0074-the-document-menu-is-a-menu.md) | The document's ⋯ menu is a menu like any other: one item a line in groups with lines between, Source and History ticked when shown, each item's keys at its right, when it was saved in a line at its foot, arrow keys between items |
| [0075](0075-review-fixes.md) | What a review of security, the network and the data found, and the fixes (`PROTOCOL` 6): access codes kept per server; `Host` checked and no open CORS; `.kuraa` files never through links, links refused in pushes and from devices; a stranger's genesis never counts, a seal kept to; `unlink` and `admit` so revoked or expired links let no one in; no clock in the policy; live edits judged by who made them; rooms no one is in start again from a changed file; marks kept through the room; merges free of local git settings; footnotes not moved as people edit; unsent edits carried into a new room |
